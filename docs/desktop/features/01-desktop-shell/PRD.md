# 桌面壳 — 产品需求文档

> 版本: v0.1 | 日期: 2026-06-25 | 状态: 草案

---

## 1. 产品概述

### 1.1 产品定位

桌面壳是 Electron 运行时，负责管理 Python 进程生命周期、窗口、托盘、打包分发和自动更新。不包含具体业务 UI。

### 1.2 核心价值

| 痛点 | 解决 |
|------|------|
| 需要手动启动 SmallShrimp Server | 一键启动，托盘管理 |
| 分布散落的脚本和命令行 | 单一可执行安装包 |

## 2. 功能范围

### 2.1 MVP（P0）

| 模块 | 功能 | 说明 |

## 3. 技术架构

### 3.1 整体架构

```
┌─────────────────────────────────────────────────┐
│                Electron Desktop                  │
│  ┌─────────────────────────────────────────────┐  │
│  │           Main Process (Node.js)             │  │
│  │  ┌───────────┐  ┌───────────┐  ┌──────────┐ │  │
│  │  │ Python 进程│  │  托盘管理  │  │ 自动更新  │ │  │
│  │  │ 生命周期   │  │  窗口管理  │  │ (electron │ │  │
│  │  │ (spawn)   │  │           │  │ -updater) │ │  │
│  │  └───────────┘  └───────────┘  └──────────┘ │  │
│  └─────────────────────────────────────────────┘  │
│                      │ IPC                        │
│  ┌──────────────────▼──────────────────────────┐  │
│  │         Renderer Process (React UI)          │  │
│  │         @ref: 01~06 各需求 PRD               │  │
│  └──────────────────┬──────────────────────────┘  │
│                     │ HTTP + WebSocket             │
│  ┌──────────────────▼──────────────────────────┐  │
│  │         SmallShrimp Server (Python)          │  │
│  └─────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

### 3.2 技术选型

| 层面 | 方案 | 理由 |
|------|------|------|
| **桌面壳** | Electron 28+ | 生态丰富、Node.js 管理 Python 子进程 |
| **前端框架** | React 18 + TypeScript | @ref: 01-agent-chat |
| **样式** | Tailwind CSS + shadcn/ui | 开发快、组件美观 |
| **状态管理** | Zustand | 轻量 |
| **打包** | electron-builder → .exe(NSIS) / .dmg / .AppImage | 跨平台 |
| **进程管理** | Node.js `child_process.spawn` | 原生管理 Python |

### 3.3 IPC 通信设计

```
Renderer (React)              Main Process (Node)          SmallShrimp (Python)
     │                               │                              │
     │── IPC: 'start-server' ───────▶│── child_process.spawn ──────▶│
     │                               │── health check (http) ──────▶│
     │                               │◀── server ready ────────────│
     │◀── IPC: 'server-status' ─────│                              │
     │                               │                              │
     │── HTTP/WS 直连 localhost ─────────────────────────────────▶│
     │  (数据通信不经过 Main Process)  │                              │
```

- **进程生命周期**：Main Process 通过 `child_process.spawn` 管理 Python 子进程
- **Main ↔ Renderer 通信**：Electron IPC（`ipcMain` / `ipcRenderer`）
- **数据通信**：Renderer 通过 HTTP/WebSocket 直连 Server，零额外延迟
- **Main Process 职责**：进程管理、窗口管理、托盘、系统通知、自动更新、文件读写

## 4. 模块详细设计

### 4.1 进程管理

```
状态机:
  [未启动] ──点击启动──▶ [启动中] ──健康检查通过──▶ [运行中]
      ▲                      │                          │
      └──────崩溃/手动停止────┘                          │
                                                         │
                                                    [运行中] ──错误──▶ [异常]
```

- 启动时自动查找 Python 环境（优先 `.venv`）
- 健康检查：轮询 `/health` 端点，超时 30 秒提示失败
- 崩溃自动重启（可配置，默认开启）
- 托盘图标状态：灰色=未启动、黄色=启动中、绿色=运行中、红色=异常

## 6. 风险 & 缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Python 环境检测失败 | 无法启动 | 支持手动指定路径；内置诊断 |
| 跨平台打包复杂 | 延迟发布 | 先聚焦 Windows |
| Server API 不满足前端 | 前端阻塞 | MVP 阶段通过直接读文件绕过 |
